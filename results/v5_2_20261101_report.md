# v5.2 限寄存器实验（2026-11-01）
> 文件整理：本报告提及的零散日志/CSV/本轮 NCU 报告现已原样归入同目录 v5_2_20261101_raw.zip；历史内容与测量数值未改变。

结论：__launch_bounds__(256, 4) 将 v5.1 的 65 registers/thread 降为 64，无 spill，恢复 4 blocks/SM 的寄存器驻留上限。但在本机 1024³、三批重复计时下，没有证据表明 v5.2 相比 v4 或 v5.1 有稳定提升。保留独立实验版本，不替换基线。

## 改动及机制

- 新增 kernels/hgemm_v5_2.cu，由 v5.1 独立复制；除符号名称及说明注释，唯一 kernel 设计变更是添加 __launch_bounds__(256, 4)。
- include/hgemm.cuh 增加 launcher 声明；根 CMakeLists.txt 将新文件加入现有 bench_hgemm。
- benchmark/bench_hgemm.cu 原有表格加入 v5.2，仍预热 5 次/计时 20 次；扩展验证包括 v5.2，--profile 支持 v5_2；新增 --bench-v5-2 做本轮对照。原 --bench-compare 和 --bench-steady 的三个版本和参数保留。
- 没有新增目录。v0～v5.1 kernel 的 SHA256 全部保持一致；修改前 benchmark/CMake 内容保存在同目录 *_before.txt，历史结果未覆盖。

256-thread block、64×64 输出 tile、BK=16。每线程仍计算行列间隔 16 的 4×4 输出，每轮各搬运两份 A/B half2；两份 shared buffer 各自被安全生产/消费。
cp.async commit/wait 的 per-thread 语义与两个 __syncthreads() 完全保留。第一个 barrier 在各线程完成当前 tile 后允许跨线程消费；第二个 barrier 防止旧 tile 尚被读取时就被复用覆盖。尾轮 wait_group 0 排空。
奇数 K/N 继续回退 v5 标量路径，不能算作 v5.2 双缓冲路径的测试或性能收益。

launch bounds 是编译器资源目标，不是运行时保证总有四个 block 驻留；编译器可能用额外指令或 local memory 换取更少寄存器。语义依据：[CUDA 12.8 Programming Guide — Launch Bounds](https://docs.nvidia.com/cuda/archive/12.8.0/cuda-c-programming-guide/index.html#launch-bounds)。

## 编译与正确性

WSL Ubuntu 24.04，RTX 3060 Laptop 6 GB，sm_86，Windows driver 591.74；NVCC 12.8.61、g++ 13.3、CMake 3.28.3，NCU / Compute Sanitizer 2025.1。
实际编译选项 -std=c++17 -O3 -lineinfo --ptxas-options=-v，生成 compute_86/sm_86；未使用 fast-math 或全局 maxrregcount。

| 编译资源 | v4 | v5.1 | v5.2 |
|---|---:|---:|---:|
| registers/thread | 60 | 65 | 64 |
| static shared bytes/block | 4096 | 8192 | 8192 |
| stack frame / spill stores / spill loads bytes | 0/0/0 | 0/0/0 | 0/0/0 |

小尺寸 13 组：1×1×1、1×2×2、31×33×17、63×62×14、64×64×16、65×66×18、128×128×32、128×128×34、65×66×48、65×66×50、63×65×15、65×63×33、129×130×66。
大尺寸 1024³、1023×1025×1007。
每组分别测试随机 dyadic、连续均匀随机、交替符号三种输入，v4/v5/v5.1/v5.2 共 180 项全部 PASS，其中 v5.2 为 45 项。

所有输出与实际 half 输入生成的 CPU double 参考逐元素比较；可精确 FP32 累加的 dyadic 输入要求最终 half 输出相等。连续随机输入采用 gamma_K*sum(abs(A*B)) + 2^-11*abs(reference) + 2^-25 的误差界，gamma_K=K*2^-24/(1-K*2^-24)。输出预填 NaN 检查漏写，使用 nonblocking stream。
小尺寸完整套件 memcheck/synccheck 为 0 errors，racecheck 为 0 errors、0 warnings。原 1024³ cuBLAS 对照命令也正常通过（此宽容差检查只是补充）。
上述是有限测试证据；不包含非有限输入、未对齐基址、零/负尺寸或超大整数索引。

## 无 NCU 计时

矩阵固定 1024³，固定种子的 dyadic half 输入、重复访问相同 A/B（缓存复用场景）。3 个独立进程/批次，每批先交替预热三个版本共 3000 launches，再运行 12 轮；每项预热 20 次，CUDA event 计时 200 次，除以 200 得到每 launch 时延。每版本总计 36 个计时观测、7200 次计时 launch。
轮次以 v4→v5.1→v5.2、v5.1→v5.2→v4、v5.2→v4→v5.1 循环，平衡执行位置。所有计时先完成，之后才启动 NCU，sanitizer 与计时也不重叠。

| 批次 | v4 median ms | v5.1 median ms | v5.2 median ms | 配对 v4/v5.2 median | 配对 v5.1/v5.2 median |
|---|---:|---:|---:|---:|---:|
| 0 | 0.550495 | 0.566779 | 0.546571 | 1.0063× | 1.0106× |
| 1 | 0.554174 | 0.540839 | 0.537797 | 1.0158× | 1.0084× |
| 2 | 0.583967 | 0.583045 | 0.574684 | 0.9919× | 0.9688× |

配对比值按同一轮 baseline 时延 / v5.2 时延计算，大于 1 才是 v5.2 更快。三个版本独立中位数的比值并不等于配对比值的中位数，第三批清楚说明了这一点。
v5.2 相比 v4 的胜出轮数为 7/12、8/12、6/12，相比 v5.1 为 8/12、7/12、4/12；收益方向没有跨批次保持一致。

| 36 个观测合并（仅描述性） | median ms | min–max ms | median 时延换算 TFLOPS |
|---|---:|---:|---:|
| v4 | 0.558405 | 0.529536–0.673050 | 3.8457 |
| v5.1 | 0.553158 | 0.530355–0.655509 | 3.8822 |
| v5.2 | 0.561508 | 0.529725–0.685640 | 3.8245 |

GPU 未锁频且有桌面负载。包含预热的遥测范围：SM 1875–1987 MHz，显存 7000 MHz，温度 56–71°C，功耗 42.63–130.37 W。样本之间有热状态、频率及时间相关性，不作为独立同分布观测，也未将 min–max 当作置信区间。波动大于多数中位收益，当前结果不能证明更快，也不能精确判定极小幅度的真实退化。

## 独立 NCU 与 SASS

每版本单次 1024³ launch，约 30 replay passes。采集 LaunchStats、Occupancy、MemoryWorkloadAnalysis_Tables、SchedulerStats、WarpStateStats，并补充动态总指令数及 local load/store sectors。保持 NCU 默认时钟/缓存控制，无应用预热。

| 指标 | v4 | v5.1 | v5.2 |
|---|---:|---:|---:|
| allocated registers/thread | 64 | 72 | 64 |
| registers block limit/SM | 4 | 3 | 4 |
| shared block limit/SM | 12 | 7 | 7 |
| achieved occupancy | 57.63% | 45.65% | 57.62% |
| eligible warps/scheduler/cycle | 2.217 | 2.104 | 2.591 |
| issue active | 67.40% | 67.16% | 67.67% |
| smsp__inst_executed.sum | 71,211,008 | 72,271,872 | 72,370,176 |
| shared load instructions | 10,485,760 | 10,485,760 | 10,485,760 |
| LDGSTS cache access | 0 | 524,288 | 524,288 |
| local load/store sectors | 0/0 | 0/0 | 0/0 |

v5.2 理论 occupancy 从 v5.1 的 50% 恢复到 66.67%，但 issue active 仅增加约 0.51 个百分点。寄存器压力改善并没有等比例转化为发射效率。
v5.2 动态指令增加 98,304（约 0.136%）；SASS 静态指令数量反而减少（825→809，含 padding/control 等），不能用静态指令数量代替执行次数。编译器确实改变了地址和控制指令安排；没有观察到 local-memory spill。
shared loads、FP32 计算映射、异步搬运量和两个 barrier 未减少。这些证据与“occupancy 提升但端到端收益不稳定”一致；并不证明那 0.136% 额外指令独自抵消了收益，也没有把任何 stall/bank-conflict 比例换算成耗时。

NCU 内时延 v4=2.536096 ms、v5.1=1.052704 ms、v5.2=1.048928 ms。v4 明显偏离独立 benchmark，默认 profiler 条件和单次测量不支持将这些数字作端到端速度比较；本报告性能结论仅使用无 NCU 计时。

## 复现

```bash
cmake -S . -B build -DHGEMM_PTXAS_VERBOSE=ON
cmake --build build -j4
./build/bench_hgemm --test
./build/bench_hgemm --test-large
/usr/local/cuda-12.8/bin/compute-sanitizer --tool memcheck --error-exitcode 3 ./build/bench_hgemm --test
/usr/local/cuda-12.8/bin/compute-sanitizer --tool racecheck --error-exitcode 3 ./build/bench_hgemm --test
/usr/local/cuda-12.8/bin/compute-sanitizer --tool synccheck --error-exitcode 3 ./build/bench_hgemm --test
./build/bench_hgemm --bench-v5-2
/usr/local/cuda-12.8/bin/ncu --launch-count 1 --section LaunchStats --section Occupancy --section MemoryWorkloadAnalysis_Tables --section SchedulerStats --section WarpStateStats --metrics smsp__inst_executed.sum,l1tex__t_sectors_pipe_lsu_mem_local_op_ld.sum,l1tex__t_sectors_pipe_lsu_mem_local_op_st.sum -o results/ncu/v5_2_next ./build/bench_hgemm --profile v5_2
```

--bench-v5-2 在三个独立进程各运行一次；Profile 的版本可替换为 v4/v5_1，报告文件名也对应替换且使用新名称。不要把 NCU 包裹在普通计时命令外。
原 ./build/bench_hgemm [M N K] 已包含 v5.2 表格，但固定顺序且重复次数较少，不用于本次稳定性判断。

所有本轮产物均以 v5_2_20261101_ 为前缀。results/ 保存编译、正确性、sanitizer、三批 bench CSV、telemetry、原始 NCU CSV、summary、SASS 和执行命令记录；results/ncu/ 保存三个 .ncu-rep。

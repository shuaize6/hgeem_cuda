## 静态时序审查

256 threads，16×16 block。线程 (tx,ty) 累加 C[blockRow*64+ty+i*16][blockCol*64+tx+j*16]，i,j=0..3。
每线程以 index=tid+pass*256 搬运两份 A half2 和两份 B half2。
A 映射到 (index/8,2*(index%8))；B 映射到 (index/32,2*(index%32))。

prologue 提交 tile 0；循环提交 tile t+1 到另一缓冲，wait_group 1 完成该线程的 tile t。
第一处 __syncthreads() 让所有生产线程完成当前 tile 后才能跨线程消费。
计算后的第二处 __syncthreads() 保证全部消费者读完，下一轮才可把 tile t+2 写入原缓冲。
末轮 wait_group 0 排空剩余拷贝。所有分支条件在 block 内一致。
commit/wait group 是 per-thread，wait_group 本身不是 block barrier。
语义核对：[NVIDIA PTX ISA](https://docs.nvidia.com/cuda/archive/12.1.1/parallel-thread-execution/index.html#data-movement-and-conversion-instructions-cp-async-wait-group-cp-async-wait-all)。

在正尺寸且基址满足 4-byte 对齐的约定下，偶数 K/N 保证 half2 行首及每次偏移对齐；无效 pair 使用安全基址和 src-size=0 零填充。
偶数尾 K 不存在仅一个 half 合法的 pair。奇数 K 或 N 由 launcher 回退 v5 标量路径。
本轮没有验证偏移 2-byte 的输入指针、零/负尺寸、超大索引溢出、非有限输入，不能将结论推广到这些接口条件。

## 正确性结果

- 小尺寸 13 组：1×1×1、1×2×2、31×33×17、63×62×14、64×64×16、65×66×18、128×128×32、128×128×34、65×66×48、65×66×50、63×65×15、65×63×33、129×130×66。
- 大尺寸：1024³、1023×1025×1007。
- 每组测试随机 dyadic、均匀随机、交替符号三种输入，三个版本，共 135 项全部 PASS。
- 每个输出都与量化后的 half 输入生成的 CPU double 参考比较。dyadic 和交替符号输入在这些尺寸可精确 FP32 累加，要求最终 half 结果相等。
- 连续随机输入采用 gamma_K*sum(abs(A*B)) + 2^-11*abs(reference) + 2^-25 的误差界，gamma_K=K*2^-24/(1-K*2^-24)。这不是算法正确性的穷尽证明。
- 输出预填 NaN 检测漏写，使用非默认 nonblocking stream；CUDA API、launch 和同步错误均检查。
- 小尺寸完整套件 memcheck/synccheck 为 0 errors，racecheck 为 0 errors/0 warnings。

## 非 NCU 计时

RTX 3060 Laptop 6 GB / sm_86，Windows driver 591.74，WSL Ubuntu 24.04，NVCC 12.8.61，g++ 13.3，CMake 3.28.3；-O3 -lineinfo，Release，无 fast-math。
NCU 和 sanitizer 均为 2025.1。GPU 未锁频、未隔离桌面负载。
输入采用固定种子 dyadic 数据；1024³；固定 A/B 地址重复执行（缓存复用工作负载）。
每批 9 轮，每轮随机顺序覆盖三个版本；每项预热 20 次、CUDA event 计时 100 次，报告每次 launch 平均值的中位数。
steady 批额外轮流运行三个版本共 3000 次预热。两批原始数据均保留。

| 版本 | 第一批 median ms | steady median ms | steady min–max ms | steady TFLOPS |
|---|---:|---:|---:|---:|
| v4 | 0.556954 | 0.539156 | 0.519035–0.552069 | 3.9830 |
| v5 | 0.566856 | 0.531415 | 0.521861–0.561725 | 4.0411 |
| v5.1 | 0.540877 | 0.536340 | 0.523366–0.560415 | 4.0040 |

逐轮配对 v4/v5.1 时延比中位数分别为 1.01275 和 0.99716。steady 单轮比值范围 0.93175–1.05085。
median 比值和比值的 median 不是同一个统计量；不能只比较独立中位数就宣称稳定提升。
第一批频率从 1522 MHz 升到约 1940 MHz；steady 后段约 1927–1935 MHz、64°C、124 W。
统计范围不是置信区间；9 轮、同一进程、未锁频，不足以支持很小的稳定增益。

## 独立 NCU 结果与解释

每个版本单次 launch，采集 LaunchStats、Occupancy、MemoryWorkloadAnalysis_Tables、SchedulerStats、WarpStateStats，每次约 30 replay passes。
本配置未进行应用预热，默认 profiler 缓存/时钟控制；NCU 时间约 1.03–1.06 ms，不用于普通 benchmark 对比。

| 指标 | v4 | v5 | v5.1 |
|---|---:|---:|---:|
| registers/thread | 60 | 64 | 65 |
| allocated registers/thread | 64 | 64 | 72 |
| static shared bytes/block | 4096 | 4096 | 8192 |
| register block limit/SM | 4 | 4 | 3 |
| shared block limit/SM | 12 | 12 | 7 |
| achieved occupancy | 57.46% | 57.83% | 45.63% |
| eligible warps/scheduler/cycle | 2.260 | 2.518 | 2.105 |
| issue active | 67.46% | 64.78% | 67.17% |
| shared load instructions | 10,485,760 | 10,485,760 | 10,485,760 |
| ordinary global load instructions | 524,288 | 0 | 0 |
| LDGSTS cache access | 0 | 524,288 | 524,288 |

没有 register spills。v5.1 的 65 个寄存器跨过分配门槛，导致理论 occupancy 从 66.67% 降到 50%；shared memory 加倍但不是本次驻留 block 的决定性限制。
双缓冲提供下一 tile 搬运与当前计算重叠的机会，却保留了相同 shared load、FP32 算术和每 tile 两个 barrier；同时增加动态缓冲地址/控制与寄存器压力。
这些观测为收益被抵消提供证据，但本实验未做单因素消融，不能分解其端到端时间贡献，也不能把 occupancy 降幅当作性能降幅。
256 blocks / 30 SM 的尾波效应也会影响 achieved occupancy；NCU 的 estimated speedup 不是已经实现的加速。
WarpStateStats 提示缺失可选 PC sampling sample count；本轮不据此给 stall 排名或成本结论，也不把 bank-conflict 计数直接换算为耗时。

下一项最小实验：在独立 v5.2 中尝试 __launch_bounds__(256,4)，保持映射和同步不变，检验能否压至 64 registers、是否引入 spill/额外指令；再完整验证、独立计时和 NCU。本轮尚未实现此变体。

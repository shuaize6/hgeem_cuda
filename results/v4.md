# v4 结果与分析

[代码实现讲解](../doc/v4.md) · [全部结果](README.md)

**结论：half2 确实减少搬运指令，但对比 v3 尚无充分证据证明稳定显著加速；作为后续实验的独立基线保留。** 本页于 2026-11-05 根据现存日志和原始 Profile 补写；没有重新运行性能测试。

## 可追溯的计时快照

2026-11-05，RTX 3060 Laptop / sm_86，1024³、FP16 输入输出/FP32 累加，CUDA 12.8.61。普通 CLI 每项预热 5 次、CUDA events 计时 20 次，固定执行顺序，不含 NCU。原文见 [全版本总表](baseline_checks.md#snapshot-1024)。

| kernel | ms | TFLOPS | % cuBLAS |
|---|---:|---:|---:|
| v4 | 0.5563 | 3.8604 | 34.3396% |
| cuBLAS | 0.1910 | 11.2418 | 100% |

这是一轮快速对照，GPU 未锁频；不能将其与其他日期/预热方式的时延混算稳定加速比。旧版没有完整的同批多进程稳态横向测试覆盖全部 v0～v3，明确保留这个证据缺口。

## 正确性记录

现存日志明确记录本版在 1024³、31×33×17、1023×1025×1007 的 cuBLAS 对照 PASS，分别见 [全尺寸](baseline_checks.md#snapshot-1024)、[短 K / 小边界](baseline_checks.md#boundary-31-33-17)、[奇数大矩阵](baseline_checks.md#odd-1023-1025-1007)。标准入口的容差为 atol=rtol=1e-2，PASS 不等于每个输出逐位相同。

[v5.1 阶段报告](v5_1_20261101_report.md) 保存了本版 13 组小尺寸与 2 组大尺寸、3 种输入，共 45 项全输出 CPU double 检查，以及小尺寸三种 sanitizer 的历史通过记录；[对应原文](v5_1_20261101_records.md) 可直接查看。该扩展测试发生在后续 H2D stream 修复之前，应按历史记录理解；当前代码已修复，本文没有声称本次重跑了这套测试。普通默认 stream 总表不受该跨 stream 问题影响。

## Profile 解释

`v4_1024.ncu-rep` 的 global load 指令为 524,288，较 v3 的 1,048,576 减半；shared load 仍为 10,485,760，说明计算阶段的数据读取没有随向量搬运一起减少。寄存器为 60，shared 为 4096 bytes。这里的 global load 指令减半不代表 DRAM 字节减半。

本次从现有 `.ncu-rep` 离线导出 [legacy_profile.csv](legacy_profile.csv)，没有重新采样 GPU。CSV 的 shared 容量统一换算为 bytes，空字段表示该报告未采集该指标；不能视为 0。采集时期的全部环境参数没有完整留存，不用 NCU 内时延代替独立 benchmark。

## 后续同批交错计时

2026-11-01 的 steady 批（1024³，3000 次交替预热、9 轮、每项 20 次预热/100 次计时）记录 v4=0.539156 ms、v5=0.531415 ms、v5.1=0.536340 ms。波动和配对结果不足以支持微小的稳定收益，详情见 [v5.1 报告](v5_1_20261101_report.md)。

## 如何复现现有入口

```bash
./build/bench_hgemm 1024 1024 1024
./build/bench_hgemm 31 33 17
./build/bench_hgemm 1023 1025 1007
```

这些命令会运行当下全部已注册版本；历史日志只包含当时已经实现的版本。v4 的实现机制见 [学习文档](../doc/v4.md)。

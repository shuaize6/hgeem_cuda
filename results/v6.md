# v6：Tensor Core WMMA（2026-11-01）

**结论：最终 v6 在本机 1024³ 的三批实验中，稳定快于 v4/v5.2，约 1.55×；达到本次 cuBLAS 吞吐的约 46.6%，尚未追平。**

## 实现

`kernels/hgemm_v6.cu` 接入原 `include/hgemm.cuh`、`benchmark/bench_hgemm.cu` 和根 CMake，沿用 `build/bench_hgemm`。v0～v5.2 kernel 内容保持不变，指纹核验通过。

先验证 32×32×16、4 warp 的基础 WMMA 版本：中位时延 0.4968 ms，Tensor pipe active 仅 8.33%。该版本保存在原 `kernels/variants/hgemm_v6_32x32.cu`，不加入当前构建。

最终版本采用 64×64×32 tile、256 threads/8 warp，每个 warp 负责相邻的 32×16 输出，维护两个 FP32 accumulator fragment。沿 K 每次搬运 32 个元素，再执行两个 k16 步骤；所有边界补零，奇数尺寸也走 WMMA，不回退旧 kernel。

shared A/B 采用 32-byte 对齐，leading dimension 分别为 32/64 个 half；warp 子块偏移仍满足对齐。load/mma/store 由完整 warp 一致执行。两次 block barrier 分别保证跨 warp 生产完成、消费者读完再覆盖。最终输出暂存与输入 tile 共用一个 union；最后一轮计算后的 block barrier 保证输入生命周期结束，输出写 shared 后再做 block barrier 和带掩码的 half 写回。没有假定 fragment 元素的 lane 映射。

接口依据：[CUDA 12.8 WMMA 文档](https://docs.nvidia.com/cuda/archive/12.8.0/cuda-c-programming-guide/index.html#warp-matrix-functions)。本阶段没有叠加 cp.async，先验证 Tensor Core 与数据复用。

## 正确性与编译

- 基础版和最终版各通过 60 项全元素 CPU double 参考检查：18 组小尺寸及 1024³、1023×1025×1007，每组 3 种输入（随机 dyadic、连续随机、交替符号）。覆盖 K=1/2/14/15/16/17/18/32/33/34/48/50/66、16/32/64 tile 边界及奇数 M/N/K。
- 精确可累加输入要求最终 half 结果完全相等；连续随机输入保留原 gamma_K 累加误差界与 half 舍入误差界，未放宽。检查 NaN 漏写，使用 nonblocking stream。
- 两版各跑 memcheck/racecheck/synccheck：0 errors；racecheck 0 warnings。最终版两个大尺寸的原 cuBLAS 对照入口也 PASS。
- 最终编译：70 registers/thread、16 KiB shared/block、0 stack frame、0 spill stores/loads。
- 这些是有限测试，不覆盖非有限输入、零/负尺寸或超大整数索引；WMMA 与标量 FP32 的累加顺序可能不同。

## 无 NCU 计时

RTX 3060 Laptop 6 GB / sm_86，WSL Ubuntu 24.04，driver 591.74，NVCC 12.8.61，g++ 13.3，CMake 3.28.3，NCU/Sanitizer 2025.1。`-O3 -lineinfo`，无 fast-math。GPU 未锁频，桌面负载未隔离。

1024³，FP16 输入/输出、FP32 累加，固定输入和缓存复用；cuBLAS 沿用 `cublasGemmEx`、`CUBLAS_COMPUTE_32F`、默认 math/algorithm，与自写 kernel 使用同一 stream、输入及输出地址。
3 个独立进程，每批交替预热 4000 launches；12 轮，每项预热 20 次、CUDA events 计时 200 次。四版本轮换执行位置。计时完成后才启动 NCU；计时不含主机分配/复制及 handle 初始化。

| 1 | 0.534393 | 0.534103 | 0.344940 | 0.161462 |

v6 对 v4/v5.2 的 36 轮配对比较全部更快；对 v5.2 的各批配对加速比中位数为 1.546×、1.546×、1.540×。cuBLAS 在所有轮次仍更快。
遥测（含预热）：SM 1890–1980 MHz、显存 7000 MHz、57–72°C、41.43–130.21 W。范围不是置信区间，样本存在时间相关性；“稳定”仅指本机本次 1024³ 三批结果，不推广到所有尺寸。

## 独立 Profile 与后续方向

每版本单 launch、约 31 replay passes，默认 NCU 时钟/缓存控制，无应用预热。采集 LaunchStats、Occupancy、SpeedOfLight、SchedulerStats、MemoryWorkloadAnalysis_Tables 及 Tensor/总指令数。NCU 内时延不用于性能结论。

| 指标 | v5.2 | 最终 v6 | cuBLAS |
|---|---:|---:|---:|
| registers/thread | 64 | 70 | 218 |
| static shared KiB/block | 8 | 16 | 48 |
| achieved occupancy | 57.88% | 46.16% | 16.66% |
| Tensor pipe active（elapsed %） | 0 | 11.47% | 24.86% |
| Tensor 指令计数 | 0 | 524,288 | 524,288 |
| 总动态指令计数 | 72,370,176 | 31,156,224 | 1,159,424 |

cuBLAS 实际选择 `ampere_fp16_s16816gemm_fp16_256x128_ldg8_f2f_stages_32x3_nn`，已确认使用 Tensor Core。v6 SASS 也出现 HMMA。
扩大 tile 将基础版约 6665 万动态指令降到约 3116 万，但仍远高于本次 cuBLAS。低 occupancy 的 cuBLAS 反而更快，说明继续追求 occupancy 数值不是主要方向。指令数/利用率只是解释线索，不能直接换算为耗时成本。

**建议下一项 v6.1 单变量实验：向量化 Global→Shared 搬运，增加对齐快路径并保留边界掩码，减少标量加载与地址处理。** 验证有效后再研究更大的每-warp 输出 tile，以及 cp.async 多阶段流水线；不要一次把这些设计混在一起。

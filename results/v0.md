## 可追溯的计时快照

2026-11-05，RTX 3060 Laptop / sm_86，1024³、FP16 输入输出/FP32 累加，CUDA 12.8.61。普通 CLI 每项预热 5 次、CUDA events 计时 20 次，固定执行顺序，不含 NCU。原文见 [全版本总表](baseline_checks.md#snapshot-1024)。

| kernel | ms | TFLOPS | % cuBLAS |

| v0 | 2.6434 | 0.8124 | 7.2266% |

这是一轮快速对照，GPU 未锁频；不能将其与其他日期/预热方式的时延混算稳定加速比。旧版没有完整的同批多进程稳态横向测试覆盖全部 v0～v3，明确保留这个证据缺口。

## 正确性记录

现存日志明确记录本版在 1024³、31×33×17、1023×1025×1007 的 cuBLAS 对照 PASS，分别见 [全尺寸](baseline_checks.md#snapshot-1024)、[短 K / 小边界](baseline_checks.md#boundary-31-33-17)、[奇数大矩阵](baseline_checks.md#odd-1023-1025-1007)。标准入口的容差为 atol=rtol=1e-2，PASS 不等于每个输出逐位相同。

没有找到针对本版独立保存的全输出 CPU double 套件或三种 sanitizer 报告。当前扩展 `--test` 从 v4 开始，不能把 v4～v6.3 的检查计数算到本版。交接文档还提到 1000³，但此次没有找到对应的独立原始日志，所以不把它加入上面的已核实清单。

## Profile 解释

历史 `v0_1024.ncu-rep` 为 26 registers/thread、0 shared bytes、约 98.26% achieved occupancy。即便 occupancy 很高也不代表高吞吐：该版本没有 shared/register tile 复用。已有记录没有保存本版所有访存指标，不能填补或推断未采集的计数。

本次从现有 `.ncu-rep` 离线导出 [legacy_profile.csv](legacy_profile.csv)，没有重新采样 GPU。CSV 的 shared 容量统一换算为 bytes，空字段表示该报告未采集该指标；不能视为 0。采集时期的全部环境参数没有完整留存，不用 NCU 内时延代替独立 benchmark。

## 如何复现现有入口

```bash
./build/bench_hgemm 1024 1024 1024
./build/bench_hgemm 31 33 17
./build/bench_hgemm 1023 1025 1007
```

这些命令会运行当下全部已注册版本；历史日志只包含当时已经实现的版本。v0 的实现机制见 [学习文档](../doc/v0.md)。

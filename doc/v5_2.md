# v5.2：限制寄存器的独立实验

[上一版 v5.1](v5_1.md) · [学习目录](README.md) · [下一版 v6](v6.md)

对应当前源码：[kernel](../kernels/hgemm_v5_2.cu#L91)、[launcher](../kernels/hgemm_v5_2.cu#L198)。测量与测试证据见 [结果分析](../results/v5_2_20261101_report.md)。本页解释实现，2026-11-05 核对源码，未重新测量性能。

## 本版只有一个核心设计改动

从 v5.1 独立复制，在 kernel 上增加：

```cpp
__global__ __launch_bounds__(256, 4) void hgemm_v5_2_kernel(...)
```

第一个参数描述每 block 最大线程数，第二个参数给编译器一个每 SM 至少容纳这些 block 的资源优化目标。它不是“每线程最多四个寄存器”，也不是运行时保证有四个 block 同时执行。

## 没有变化的部分

- 16×16 threads，64×64×16 tile，两个 A/B shared buffer。
- 每线程 16 个 FP32 输出，行列坐标都相隔 16。
- 预加载 tile 0，预取下一 tile，wait_group 1/0，以及计算前后两个 block barrier。
- 奇数 K/N 仍通过 launcher 回退 v5。

因此阅读本版时，先完整理解 [v5.1 的时序](v5_1.md)，再用源码 diff 定位这个注解。

## 为什么 65→64 值得实验

历史 sm_86 编译中，v5.1 使用 65 个寄存器，但分配数为每线程 72；v5.2 编译为 64，分配数也为 64。所测寄存器限制的 blocks/SM 从 3 增至 4，没有 spill。这些数值属于该工具链和源码，不是注解永远会产生的固定结果。

减少寄存器可能增加重算、控制指令或 spill，所以要同时检查 ptxas、SASS 和运行数据，不能只看 registers 数值。

## 如何判断实验是否成功

资源目标达到了；端到端性能并未在三批测量中稳定改善。shared 读取、乘加工作量和 barrier 没有减少，资源指标更好不自动等于 kernel 更快。保留这一独立版本有助于学习如何记录负结果。

## 阅读与验证

先从 launcher 确认 block/grid，再沿 kernel 的加载、同步、计算、输出顺序阅读。可运行以下现有入口：

```bash
./build/bench_hgemm --test
```

该命令的实际覆盖范围以 [测试索引](../results/README.md) 为准；测试命令示例不代表本次文档整理重新执行过验证。

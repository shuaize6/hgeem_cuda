## 从线程外积切换到 warp 矩阵运算

使用 `<mma.h>` 的 WMMA 接口，A/B fragment 的逻辑形状为 16×16×16，输入 half，累加 float。`mma_sync` 由整个 warp 协作执行；fragment 内的元素如何分布到 lane 不由本代码假定。

最终构建版本是 64×64×32 tile、256 threads/8 warp。早期 32×32×16、4 warp 实验留在 `kernels/variants/hgemm_v6_32x32.cu`，没有加入根 CMake。

## warp 映射

```cpp
warp = threadIdx.x / 32;
warpRow = (warp / 4) * 32;
warpCol = (warp % 4) * 16;
```

warp 0～3 覆盖上半个 32×64，warp 4～7 覆盖下半个。每个 warp 维护两个 16×16 accumulator，合起来是 32×16 输出。

## 一轮 K tile

256 个线程按 `index=tid; index<2048; index+=256` 标量搬运 A，再按 B 的列跨度解码 index 搬 B；每线程各搬 8 个 half。越界位置补零，所有 warp 始终完整参加 WMMA。

barrier 后，BK=32 拆成 k=0、16 两步。每步加载一次 B fragment，然后依次加载上下两个 A fragment，更新两个 accumulator。这样 B fragment 复用了两次。第二个 barrier 后才允许覆盖输入 tile。

## 为什么通过 shared 写输出

`store_matrix_sync` 把 fragment 存为已知的行主序 float 矩阵，再由线程按线性 index 读取、转换为 half，并检查真实 M/N 边界。这个步骤避免直接猜测 fragment 元素对应哪个全局坐标。

输入 As/Bs 与 float Cs 放进 union：K 循环结束且 barrier 完成后，输入不再被读取，可以复用同一片 shared。输入需要 8 KiB，输出需要 16 KiB，实际分配取最大值 16 KiB。

WMMA 起始指针采用 32-byte 对齐；half leading dimension 为 8 的倍数，子块指针也保持所需对齐。warp collective 不能代替生产者/消费者之间的 block barrier。

下一版保留运算和 warp 映射，只调整 shared 行跨度。

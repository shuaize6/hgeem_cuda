## half2 用在什么地方

该版本用 half2 打包两个 half 来搬运，计算仍然 half→float 后做 FP32 乘加，没有改成半精度累加。BM=BN=64、BK=16、256 threads、每线程 4×4 输出与 v3 相同；shared A[64][16]、B[16][64]，共 4 KiB。

## 搬运线程映射

令 `tid=ty*16+tx`。每线程执行两次 pass，`index=tid+pass*256`，覆盖每个 tile 的 512 个 half2 包：

| 对象 | shared 行 | shared 起始列 |
|---|---|---|
| A | `index/8` | `2*(index%8)` |
| B | `index/32` | `2*(index%32)` |

例如 tid=0 搬 A 行 0 和 32 的第 0/1 列，同时搬 B 行 0 和 8 的第 0/1 列。搬运映射和最终计算映射可以不同，只要整个 shared tile 被完整覆盖。

## 快路径与补零

A 要求 K 为偶数且两个元素合法；B 单独检查 N 为偶数且两个元素合法。满足时通过 `reinterpret_cast<const half2*>` 读取 4 bytes，否则逐个检查两个 half，使用 `__halves2half2` 合成并写入 shared。

这里默认输入基址来自 cudaMalloc，至少满足 4-byte 对齐。仅检查 K/N 的奇偶性不能保证任意偏移指针也对齐；当前 v4 没有 v6.2 那样的运行时地址对齐检查。

## 计算与同步

加载结束做 block barrier，然后照搬 v3 的 4×4 外积计算，读取完再 barrier。每个输出仍单独检查 M/N 边界。

预期效果是搬运指令变少，不能说搬运字节减半。历史 Profile 确认普通 global load 指令由 v3 的 1,048,576 降到 524,288，但计算阶段 shared 读取没有减少，因此整体收益有限。

## 阅读与验证

先从 launcher 确认 block/grid，再沿 kernel 的加载、同步、计算、输出顺序阅读。可运行以下现有入口：

```bash
./build/bench_hgemm --test
```

该命令的实际覆盖范围以 [测试索引](../results/README.md) 为准；测试命令示例不代表本次文档整理重新执行过验证。

## cp.async 替换了哪段路径

tile、线程和 FP32 计算仍沿用 v4。偶数 K/N 时，把 global→寄存器→shared 的显式数据搬运替换成 4-byte `cp.async.ca.shared.global`。地址计算仍需寄存器；不能说使用 cp.async 后完全不占寄存器。

`cp_async4` 先用 `__cvta_generic_to_shared` 把 shared 指针转换为指令需要的 shared 地址。有效包复制 4 bytes；无效包使用安全的全局基址，并通过 source-size=0 把目标 4 bytes 清零，不构造越界源指针。

## 每轮实际执行顺序

```text
发起当前 tile 的 A/B 拷贝
→ 当前线程 commit_group
→ 当前线程 wait_group 0
→ __syncthreads()
→ 4×4 FP32 外积计算
→ __syncthreads()
→ 下一 tile
```

一次 pass 的 half2 地址映射与 v4 相同，每线程两轮，共发出两份 A 和两份 B 的复制。

`commit_group` 与 `wait_group` 的队列属于发出指令的线程。`wait_group 0` 等待本线程之前提交的组，不等价于其他生产线程也完成了，所以后面的 block barrier 必不可少。

## 为什么叫单缓冲

只分配一套 As/Bs，总计 4 KiB。当前 tile 搬完后才计算，算完后才能覆盖；源码没有形成“下一 tile 搬运与当前 tile 计算”的跨 tile 流水线。异步指令是能力，代码是否把时间重叠起来是另一件事。

## 奇数尺寸路径

`use_async=(K%2==0)&&(N%2==0)`。任一行跨度为奇数时，两矩阵都走标量补零路径；不像 v4 那样分别决定 A/B 是否向量化。偶数尾 K 的合法数据成对出现，不需要处理仅一个 half 有效的异步包。

原生异步路径仍假设基址 4-byte 对齐。v5.1 将增加第二套 shared buffer，尝试真正的跨 tile 重叠。

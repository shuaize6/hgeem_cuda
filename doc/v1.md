对应当前源码：[kernel](../kernels/hgemm_v1.cu#L5)、[launcher](../kernels/hgemm_v1.cu#L89)。测量与测试证据见 [结果分析](../results/v1.md)。本页解释实现，2026-11-05 核对源码，未重新测量性能。

## 相比 v0 改了什么

仍是每线程一个输出，block 仍有 16×16 个线程，但沿 K 每次处理 16 个元素。新增 `As[16][16]` 和 `Bs[16][16]` 两块 half shared memory，总计 1024 bytes。

## 搬运与复用

线程 `(tx,ty)` 搬入 `A[row,tile*16+tx]` 和 `B[tile*16+ty,col]`。注意 A 的 K 坐标使用 tx，B 的 K 坐标使用 ty，它们在 shared 中统一成乘法需要的布局：

```cpp
As[ty][tx] = A[row * K + tile * 16 + tx];
Bs[ty][tx] = B[(tile * 16 + ty) * N + col];
// 省略的边界分支在实际源码中补零
sum += float(As[ty][k]) * float(Bs[k][tx]);
```

固定一个 k，`As[ty][k]` 被同一输出行的 16 个线程复用，`Bs[k][tx]` 被同一输出列的 16 个线程复用。只有一个 FP32 sum 常驻每个线程的寄存器。

## 两次同步为什么都需要

```text
协作加载当前 tile → barrier → 读取并计算 → barrier → 覆盖成下一 tile
```

第一处 `__syncthreads()` 保证其他线程加载的值已经可见；第二处保护尚未结束读取的线程。越界线程不能像 v0 那样提前 return：它们仍要补零、参加所有 barrier，只在最终写 C 时屏蔽无效坐标。

K 不是 16 的倍数时，最后一个 tile 的无效 K 元素补零，计算循环仍完整执行 16 步。

## 下一步的问题

shared 降低 global 数据重复加载，但每个乘加仍要从 shared 取 A/B。v2 让一个线程计算多个输出，以便进一步在寄存器里复用数据。

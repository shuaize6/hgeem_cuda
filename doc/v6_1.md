# v6.1：调整 WMMA 的 shared 行跨度

[上一版 v6](v6.md) · [学习目录](README.md) · [下一版 v6.2](v6_2.md)

对应当前源码：[kernel](../kernels/hgemm_v6_1.cu#L15)、[launcher](../kernels/hgemm_v6_1.cu#L100)。测量与测试证据见 [结果分析](../results/v6_1_v6_2.md)。本页解释实现，2026-11-05 核对源码，未重新测量性能。

## 逻辑形状与物理跨度分开

BM=BN=64、BK=32 不变。原 A shared 的物理行长 32 half，B 是 64 half；本版引入：

```cpp
constexpr int AS = BK + 16; // 48 half
constexpr int BS = BN + 16; // 80 half
half As[BM][AS];
half Bs[BK][BS];
```

padding 不属于矩阵的有效数据，不额外参加乘法。global A/B 的行跨度仍是 K/N。

## 地址改变在哪里

同一个逻辑 `As[row][col]`，物理 half 偏移由 `row*32+col` 变成 `row*48+col`；B 对应由 `row*64+col` 变成 `row*80+col`。改变行间地址有机会减少不同访问落到同一 shared bank 的冲突。

加载到 fragment 的 leading dimension 也必须同步修改：

```cpp
load_matrix_sync(b, &storage.input.Bs[k][warpCol], BS);
load_matrix_sync(a, &storage.input.As[warpRow+i*16][k], AS);
```

只改数组大小、忘记改 WMMA 的步长，会让库按错误的行跨度读取数据，属于正确性错误。

## 对齐与存储量

48/80 都是 8 的倍数；每行字节数为 96/160，结合 32-byte shared 基址和当前子块偏移，满足代码的 WMMA 对齐要求。

A/B 输入区总共 11 KiB，比 v6 的 8 KiB 增加；但 union 里的输出 Cs 仍占 16 KiB，所以最终 shared 分配仍为 16 KiB，不是 27 KiB。

## 哪些因素保持不变

256 threads、8 warp、每 warp 32×16 输出、标量 global→shared 搬运、两个 K-loop barrier 以及最终输出路径都保持不变。历史 Profile 显示 shared read 冲突显著下降但没有归零，独立计时也改善。

不要把这组 padding 当成通用最优值。它针对当前 WMMA 形状、行主序和 warp 映射；下一版在此基础上只改搬运粒度。

## 阅读与验证

先从 launcher 确认 block/grid，再沿 kernel 的加载、同步、计算、输出顺序阅读。可运行以下现有入口：

```bash
./build/bench_hgemm --test-v6-1
```

该命令的实际覆盖范围以 [测试索引](../results/README.md) 为准；测试命令示例不代表本次文档整理重新执行过验证。

# v6.3：fragment 复用与分段输出

[上一版 v6.2](v6_2.md) · [学习目录](README.md)

对应当前源码：[kernel](../kernels/hgemm_v6_3.cu#L37)、[launcher](../kernels/hgemm_v6_3.cu#L131)。测量与测试证据见 [结果分析](../results/v6_3.md)。本页解释实现，2026-11-05 核对源码，未重新测量性能。

## 复用 A 和 B 两个方向

保留 block 输出 64×64、BK=32、AS=48、BS=80；线程数改为 128，即 4 个 warp：

```cpp
warpRow = (warp / 2) * 32;
warpCol = (warp % 2) * 32;
```

每 warp 算 32×32，维护 `acc[2][2]`。每个 k16 步先加载两个 A fragment，再循环加载两个 B fragment；每个 B 与两个 A 分别相乘。因此全 block 的 fragment 加载次数由 `8*(2+1)=24` 降到 `4*(2+2)=16`，乘加总量不变。

## 搬运如何覆盖完整 tile

线程数减半后，不能继续只搬每线程一个包。源码改成 `index=tid; index<256; index+=128`，每线程搬两个 A 包、两个 B 包。各包的 row/col 解码仍使用 v6.2 的规则，load8 的对齐及边界检查完全保留。

## 为什么还要缩小输出暂存

第一版只增加 fragment 复用，保留 16 KiB shared，Profile 显示每 SM 受 shared 限制只能驻留 5 个 block；因为每 block 的 warp 数减半，实际 occupancy 明显下降。

最终改用 `Cs[32][64]`，每轮只暂存每个 warp 的一个 16×32 条带：

| 输出轮次 i | 暂存 row 0～15 写到 C 的行 | 暂存 row 16～31 写到 C 的行 |
|---|---|---|
| 0 | blockRow+0～15 | blockRow+32～47 |
| 1 | blockRow+16～31 | blockRow+48～63 |

```cpp
outputRow = blockRow + (row/16)*32 + i*16 + row%16;
```

输入区仍占 11 KiB，输出区降为 8 KiB；union 现在由输入决定大小，静态 shared 从 16→11 KiB。

## 生命周期与 barrier

K 循环的两个 barrier 不变。每轮输出先执行 WMMA store，barrier 后由线程读取 shared 并写 C，再 barrier，才允许下一轮覆盖。所有线程都参加 barrier，只有全局输出 store 按 M/N 掩码。

最终编译为 56 registers/thread，无 spill，所测 shared 限制放宽到 8 blocks/SM。不过总动态指令增加，输出也多了阶段和同步，因此小矩阵未获益。

## 如何理解结果

4096³ 三批配对都快于 v6.2；1024³ 反而变慢。当前 launcher 不按尺寸偷偷切回 v6.2，所有 v6.3 测试都执行本版 kernel。保留两个独立版本才能看到这个取舍。

## 阅读与验证


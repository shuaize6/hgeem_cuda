# v0：逐元素基线

[学习目录](README.md) · [下一版 v1](v1.md)

对应当前源码：[kernel](../kernels/hgemm_v0.cu#L3)、[launcher](../kernels/hgemm_v0.cu#L27)。测量与测试证据见 [结果分析](../results/v0.md)。本页解释实现，2026-11-05 核对源码，未重新测量性能。

## 要解决的问题

先把行主序矩阵乘法直接映射到线程，建立可以对照后续版本的实现。每个输出是 A 的一行与 B 的一列的点积，输入先从 half 转为 float，整个点积保留 FP32 累加，最后只转换一次输出。

## 线程与地址

block 为 `dim3(16,16)`，线程 `(tx,ty)` 对应：

```cpp
row = blockIdx.y * 16 + ty;
col = blockIdx.x * 16 + tx;
A_index = row * K + k;
B_index = k * N + col;
C_index = row * N + col;
```

例如 block `(0,0)` 内线程 `(3,2)` 算 `C[2,3]`；K 循环中先读 `A[2,0]*B[0,3]`，再读 `A[2,1]*B[1,3]`，依此类推。grid 在 M/N 方向向上取整。

## 顺着代码执行

1. 计算 row/col，越界线程直接返回。本 kernel 没有 block barrier，所以这种提前退出不会使其他线程卡在同步点。
2. `float sum=0`；顺序扫描整个 K，进行 half→float 转换和乘加。
3. `__float2half_rn(sum)` 写回唯一的输出地址，线程之间没有写冲突。

## 为什么后续还要改

相邻输出重复使用 A 行或 B 列，但本代码没有显式缓存与协作复用。GPU cache/广播可能减少真实内存流量，因此不能把源码中的读取次数直接当成 DRAM 事务数。下一版把这种复用明确组织到 shared memory。

当前 v0 使用 `int` 计算部分地址；讨论和测试都限于现有尺寸，不能据此保证超大矩阵索引安全。

